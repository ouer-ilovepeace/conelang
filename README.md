# cone 0.9.6

cone 是一门直接由 `.cone` 源码生成 MASM32 汇编源文件（`.asm`）的语言。编译器用 V 0.5.2 编写，面向 Windows x86 / MASM32；生成的 `.asm` 可交给 `ml.exe` / `link.exe` 继续编译链接，也可作为文本产物直接查看。

上一版为 0.9.5。0.9.6 是 `-O1` 正确性修复版，不改语法、EBNF、类型系统、coneABI 与 SEH 生成结构。

ConeLang 现已更新至最新版本Cone0.9.p，conex64下对asm64{}块有新的支持，对函数调用、参数返回、多文件编译、报错警告、try-except、enum、__link__、__compile__等有更明确的更新与支持。

## 本版内容

**修复**

- `O1-BUG-001`：0.9.5 的块内跨行冗余写消除未建模 x86 子寄存器别名（`eax/ax/al/ah` 等），会把「以 `ax` / `al` 读出前先定义 `eax`」的活指令判为死写删除，导致结构体 `word` / `byte` 成员赋值为无来源的残留值，且不报错。0.9.6 增加寄存器别名表、子寄存器出现时退回相邻两行窗口的安全网，并把「不参与消除的写」判据由「文本含 `[`」改为「目标是内存位置」。
- 新增 `ml.exe` 实机汇编与 O0 / O1 可执行文件行为差分验证环节（0.9.5 验收缺此项）。

**改进**

- `add r,1` 由无条件禁止改为按 flags 活性选择：后续读 CF 保留 `add`，仅读其它状态位用 `inc`，flags 全死用 `lea r,[r+1]`。乘常数转移位仍不做。
- `-O1:report` 增加跳过原因分类，可看出哪些区域因冻结区或硬屏障未参与优化。
- 别名不确定时只跳过该基本块，不再整文件回退。

**前提**

- 不开启 `-O1` 时，编译与代码生成和 0.9.5 完全一致；优化逻辑只在 `generate()` 之后、`opts.o1` 为真时进入。
- `cone -s -O1 demo.cone` 与 0.9.4 起的用法兼容；五个可选子开关默认全部关闭。

## 构建与运行

```
v -prod -cc cl -cflags "/GL /O2 /Ot /Oi /Ob3" -ldflags "/LTCG /OPT:REF /OPT:ICF /STACK:16777216" .
cone -s demo.cone        # 生成 .asm
cone -s -O1 demo.cone    # 生成并优化 .asm
cone -s -ml demo.cone    # 编译并链接
cone -v                  # 版本信息
```

`-m/-l/-ml/-s/-noseh/-addm/-addl/` 及多 `.cone` 文件编译沿用 0.9.5 行为。

## 说明

- 产物是 MASM32 文本，不是机器码。`asm{}` / `asm64{}`、`seg` 段、SEH 帧链等区域在 `-O1` 下逐字冻结。
- 未实现：寄存器分配、尾调用、循环展开与强度削弱、跨语句替换型传播、跨文件过程间优化。
- 发行包为 Windows 平台，依赖本机 MASM32（`ml.exe` / `link.exe`）。
