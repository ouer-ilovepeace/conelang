===============================================================================
conex64.txt —— cone x64 语法规范
===============================================================================

适用范围：带 -llvm / -llvm:x64 编译的 Windows x64 LLVM 后端。
不带 -llvm 的默认 MASM32 / Windows x86 语法见 SYNTAX_x86.txt，两册互不覆盖。

-------------------------------------------------------------------------------
1. 编译命令与产物
-------------------------------------------------------------------------------

    cone -llvm:x64 源文件.cone
    cone -llvm:x64 -addl[/libpath:Z:\masm64\masm64\lib64] 源文件.cone

流程：.cone -> .ll（LLVM IR）-> llc.exe 出 .obj -> lld-link.exe 出 .exe。
每个源文件同时生成 <stem>.llvm.bat，里面是 llc / lld-link 的完整命令行，
可以直接改参数重跑。

目标三元组 x86_64-pc-windows-msvc，入口符号就是 end 声明的名字（不加前导
下划线）。默认链 msvcrt.lib；CRT 目录不固化，靠 -addl[/libpath:...] 或系统
LIB 提供。VS2022 UCRT 的 printf 在 ucrt.lib + vcruntime.lib，老式 msvcrt.lib
（masm64\lib64）可直接用。

    -llvm            等同 -llvm:x64
    -s               只生成 .ll 与 .llvm.bat，不跑工具链
    -O0 / -O1 / -O2 / -O3 / -Os / -Oz
                     只作用于 -llvm:x64，传给 llc -O<级别>（默认 -O0）。
                     -O2 / -O3 / -Os / -Oz 时若 llvm\bin\opt.exe 存在，
                     会先跑 opt -S -O<级别> <stem>.ll -o <stem>.opt.ll
                     做 IR 级 pass，再让 llc 编译 <stem>.opt.ll；opt.exe
                     不存在时直接 llc -O<级别>，不报错。
                     -O1[:子开关] 仍是 x86 MASM 后端的实验性优化开关，
                     在 -llvm:x64 下只等价于 -O1。
    -D[NAME]         登记一个编译期符号（可写多次，也可 -D NAME）
    -out[NAME]       多文件联合链接时指定最终 exe 名（不带 .exe）
    -llvm:x86        不支持；x86 请不带 -llvm 直接编译
    -m/-l/-ml/-lw/-lc 与 -llvm 互斥

浮点程序不需要额外链接库：编译器会在 IR 里定义 @_fltused，避免 lld-link 报
undefined symbol: _fltused。

入口函数会自动以 `ExitProcess(返回值)` 结束（见第 5 节），因此编译器会把
`kernel32.lib` 汇入链接命令（与 include 推导出的库一起去重）；`llvm.bat`
里能直接看到。若源码里已经显式调用了 ExitProcess，编译器不再插入，
此时请自己写 `include kernel32`。

多文件联合链接

    cone -llvm:x64 -O2 -out[app] a.cone b.cone c.cone

每份 .cone 各生成一份 .ll / .obj，最后**一次** lld-link 联成单个
app.exe（不带 -out 时默认用第一个源文件的 stem）。只有带 `end 名字` 的
那份单元提供入口；其余单元可以没有 end。跨单元调用请在调用方写
`func 名字(...) 返回类型` 声明，链接时由 lld-link 解析。
所有单元的 include 推导库、-addl / __link__ 参数会合并去重。
编译期自动生成的 @fuck / @_fltused / SEH 辅助全局量用 linkonce_odr /
internal 链接属性，多份 .obj 不会重复定义冲突。生成的 app.llvm.bat
里是「逐个 llc + 一次 lld-link」的完整命令；-s 时只出 .ll 与该 bat。

2. 类型
-------------------------------------------------------------------------------

    | cone      | 字节 | LLVM IR  | 说明                          |
    |-----------|------|----------|-------------------------------|
    | byte      | 1    | i8       |                               |
    | word      | 2    | i16      |                               |
    | int       | 4    | i32      | 默认整数类型                  |
    | long      | 8    | i64      |                               |
    | f32       | 4    | float    | IEEE 单精度                   |
    | f64       | 8    | double   | IEEE 双精度                   |

    unsigned / signed 只影响比较运算，不改变宽度。
    typedef 别名继承基础类型宽度。
    struct 按 Windows x64 ABI 对齐；sizeof(类型名/变量名) 编译期求值。

3. 顶层声明
-------------------------------------------------------------------------------

    变量 / 数组             int  n
                            f64 pi=3.14
                            int arr[8]
                            byte buf[4]=1,2,3,4

    数据（字符串/字节）      fmt:"float: i=%d f=%d\n",0
                            tbl:0dh,0ah,0

    结构体                  struct sample{ ratio f64  n int  small f32 }
                            struct pt{ xx int  yy int }
                            struct q align{ a byte  b int  z byte }
                            sample g={2.5,7,1.25}
                            pt origin={}

    常量                    EXCEPTION_ACCESS_VIOLATION equ 0C0000005h
                            MAX equ 100

    类型别名                typedef myint int

    入口                    end main

成员访问用 g.ratio / origin.xx；结构体数组元素、嵌套结构体成员按字节偏移
寻址。结构体常量 Type{...} 不支持，请写结构体变量的初值列表 ={...}。

宽字符串 w"..."

    在开引号前直接加 `w`（或 `W`），正文按 UTF-16LE 编码，每个 Unicode
    码元 2 字节，非 BMP 字符自动拆成代理对；结尾自带 2 字节 NUL。

        wcap:w"Cone 标题"                ; 数据定义 -> 16 字节
        wmsg:w"Hello, 世界!\n"           ; 数据定义，\\n 展开成 0A 00
        MessageBoxW(0, w"Hello", addr wcap, 0)   ; 表达式字面量

    * `w` 必须紧邻引号；`int w=1`、`w "x"`（带空格）仍是普通标识符。
    * 支持中文等非 ASCII 字符与常用转义（\\n \\r \\t \\0 \\\\ \\" \\xHH）；
      转义序列也按 2 字节码元展开（\\n -> 0A 00）。
    * 数据定义里的 w"..." 已自带 2 字节终止符，**不要再写 ,0**；窄字符串
      仍沿用源码里的 `,0`。sizeof(wcap) 按实际 UTF-16LE 字节数计算。
    * 表达式位置的 w"..." 生成私有常量并返回 ptr，可直接传给宽字符 API
      （MessageBoxW / wprintf 等）；窄 API（printf / MessageBoxA）请继续用
      普通字符串，混用会得到乱码，编译器不负责转换。
    * x86 默认后端同样支持：渲染成 MASM `db` 的十六进制字节项，
      老示例不带 w 前缀时输出逐字节不变。

enum（编译期整数常量）

    enum [名字]{ 成员[=常量表达式], 成员[=常量表达式], ... }

        enum color{ red, green, blue }        ; red=0 green=1 blue=2
        enum flags{ AA=1, BB=10, CC }         ; AA=1 BB=10 CC=11
        enum mode{ X Y Z }                    ; 空白 / 换行分隔也可以

    * 首项不带 = 时为 0，之后不带 = 时为「上一项 + 1」；带 = 时表达式
      可引用已定义的 equ 或前面的 enum 成员，编译期折叠成整数。
    * 成员之间用逗号分隔，或每个成员单独一行；带 = 的表达式不跨行。
    * 编译器在源码级把 enum 展开成等价的 `名字 equ 值` 声明序列，
      不生成任何 LLVM / MASM 伪指令；默认 x86 后端同样可用。
    * enum 名字本身登记成一个编译期符号（可供 ifdef 判断）。
    * cone 关键字大小写不敏感，`C` / `c` / `int` / `end` 等不能作成员名。

编译期条件编译

    defsym NAME                ; 登记一个编译期符号
    ifdef NAME{ ... }          ; 已定义 -> 保留本块
    ifndef NAME{ ... }         ; 未定义 -> 保留本块
    elsedef{ ... }             ; 可选，接在上面任一块之后

        defsym LOCAL_SYM
        ifdef DEBUG{
            N equ 100
            cap:"DEBUG 版",0
        }
        elsedef{
            N equ 7
            cap:"RELEASE 版",0
        }
        ifndef NEVERSET{ M equ 3 }

    符号集合 = 命令行 -D[NAME] ∪ 源码 defsym NAME ∪ `defined NAME(...)`
    宏定义 ∪ 内置 CONE_X64（-llvm:x64）/ CONE_X86（默认 x86）。
    **equ / enum 成员 / def / struct 等不自动成为符号**（避免
    `ifdef X{ X equ 1 }` 自指），要用它们判断请写 defsym 或 -D。

    整段在 cone 侧做源码级 token 过滤：未选中分支里的 equ / 变量 /
    类型 / 函数 / 语句全部不参与后续解析与代码生成，是纯编译期确定，
    不产生运行时分支。块可嵌套，块内可以是函数体语句、结构体、seg、
    数据定义等任意 cone 结构。elsedef 必须紧跟对应块的 `}`。

4. 外部符号与链接库
-------------------------------------------------------------------------------

x64 下有三种互不混淆的写法：

  (1) import 名字        —— 源码级导入：合并 std/名字.cone 或源码目录/名字.cone。
                            不产生任何链接项，和 .lib 无关。
                            import x64crt 会导入一组 CRT 外部函数声明。

  (2) func 声明          —— 声明外部函数原型，必须写返回类型：
                                func printf(:long) c int
                                func risky(:int) c int
                                func ExitProcess(:int) stdcall int
                            调用约定 c / stdcall 在 x64 下都不产生符号修饰，
                            链接符号一律原名。

  (3) include            —— 链接时导入库，默认按下面的规则：
                                include xxx        -> 链接 xxx.lib
                                include xxx.lib    -> 链接 xxx.lib
                                include xxx.yyy    -> 链接 xxx.yyy（原样）
                            include 可以是任意后缀（.inc / .obj / 自定义），
                            只有不带后缀时才补 .lib。
                            include 只影响链接命令行，不引入任何源码。

    例：include user32           -> lld-link ... user32.lib
        include kernel32.lib     -> lld-link ... kernel32.lib
        include mylib.obj        -> lld-link ... mylib.obj

win 关键字（win.* / win{}）在 x64 下不可用；外部符号一律靠 func 声明、
import x64crt 或 include 对应的库。

5. 函数定义与调用
-------------------------------------------------------------------------------

    def 名字(形参:类型, ...) [c|stdcall] [export] [返回类型]{
        ...
        return 表达式
    }

    def scale(v:f64, k:f64) f64{
        return v*k
    }
    def sum3(a:int, b:int, c:int) int{
        return a+b+c
    }
    def main() export int{
        return 0
    }

    * 返回类型写在调用约定 / export 之后；省略时按 i32 处理。
    * export 只能写在 def 上，生成 define dllexport。
    * 外部 func 声明必须写返回类型，缺返回类型是 error。
    * 函数可以互相调用、递归调用；前向声明用 func 与 def 同名。
    * 形参与返回值支持 byte/word/int/long/f32/f64 与结构体。
    * 变参函数（printf 等）按 C varargs 提升：窄整数 -> i32，f32 -> f64。

调用：

    f64 r=scale(3.5, 2.0)
    int  n=sum3(1,2,3)
    printf(addr fmt, n, r)
    MessageBoxW(0, w"宽字符", addr wcap, 0)
    risky(7)                        ; 独立调用语句，返回值丢弃

入口函数与进程退出（重要）

    `end start` 指定的入口函数**不需要、也不应该手写 `ExitProcess`**。
    编译器会把入口函数体内所有 `return`（含末尾隐含返回）生成：

        call void @ExitProcess(i32 <返回值>)
        unreachable

    非 i32 返回值会先做 trunc / sext / fptosi 转成 i32 传给 ExitProcess；
    显式 `ExitProcess(0)` 的程序完全尊重用户代码，不插入任何东西。

    原因：Windows x64 的进程入口由 `RtlUserThreadStart` 调用，入口函数若
    用 `ret` 返回，会走 `ExitThread` -> 隐式进程退出 -> loader 遍历全部
    已加载 DLL 的 detach 通知；注入型 DLL（例如 A-Volute Nahimic 的
    `AudioDevProps2.dll`）常在这条路径上解引用空指针，报 0xc0000005。
    `ExitProcess` 走 `LdrShutdownProcess`，绕开该分支。MSVC 的
    `mainCRTStartup` 末尾也是 `exit()` -> `ExitProcess`，从不 `ret`。
    所以**不要**用 `ret` 结束入口；手写 masm64 用 `ret` 同样会触发该问题。

标识符命名

    x64 下**没有 MASM32 保留字表**：`title` / `proc` / `invoke` / `mov` /
    `jmp` / `dword` / `eax` / `option` 等伪指令、汇编指令、寄存器名都是
    普通标识符，可作变量名 / 函数名 / 形参 / 结构体名 / 成员名 / 数据标签。

        int mov=11
        int eax=66
        def addup(mov:int, jmp:int) int{ return mov+jmp }
        title:"数据标签",0

    仍受限的只有 **cone 关键字**（def / end / return / int / if / for /
    try / except / import / include ...）、`fuck`（异常码保留变量）、
    `__compile__` / `__link__` 等 cone 特殊标识符。
    不带 `-llvm` 的默认 x86 后端仍按 MASM32 保留字表拒绝这些名字。

    x64 下标识符还可以含 `@` / `$` / `?`（首字符或中间都行）：

        def add@(x@:int, y?:int) export int{ return x@+y? }
        int q$st=9
        g@lobal:"data",0

    LLVM 裸标识符不接受 @ 和 ?，编译器自动把这类名字写成
    `@"add@"` / `%"x@"` / `%"p.a?b"`；`$` 是 LLVM 合法裸字符，原样输出。
    默认 x86 后端仍把 `$` 当作 MASM 当前地址立即数，不支持含 $ 的标识符。
    注意 cone 关键字大小写不敏感，与 `c` / `int` / `end` 等重名仍受限。

关于栈帧

    LLVM 在 x64 上默认**省略帧指针**（frame pointer omission）：机器码里
    看不到 `push rbp / mov rbp,rsp`，局部变量用 `rsp` 相对寻址，例如

        sub rsp,28h
        mov dword ptr [rsp+24h],1
        ...
        add rsp,28h
        ret

    `28h` = 32 字节 shadow space + 8 字节栈对齐补正（入口时 rsp ≡ 8 mod
    16，call 前必须 ≡ 0 mod 16）；`[rsp+24h]` 是 shadow space 之上的局部
    变量。这不是"优化掉了栈帧"，而是 Windows x64 ABI 本来就推荐这样做：
    unwind 由 `.pdata` / `.xdata` 表描述，不依赖 rbp 链，带 try/except
    的函数照样能正确展开。
    如需显式 rbp 帧，可给 llc 传 `-addm[-frame-pointer=all]`（取决于本机
    llc 版本）。

6. 语句与控制流
-------------------------------------------------------------------------------

    局部声明 / 初值        int i=0
                            f64 fv=3.5
                            sample s={2.5,7,1.25}
                            int a[4]
    赋值                    i=i+1
                            g.ratio=1.5
                            arr[2]=9
    自增 / 自减            i++    i--
    调用语句                printf(addr fmt, i)
    if / elseif / else     if fv>1.0{ ... } elseif fv<0.0{ ... } else{ ... }
    for                    for i<3{ ... }      或  for{ ... }（无条件）
                            break / continue 只在 for 内有效
    match / case / default match i{ case 1{...} case 2{...} default{...} }
    return                  return 表达式      （不能空 return）
    try / except            见第 7 节

整数与浮点可以混合运算：整数会按赋值 / 形参 / 返回类型自动 sitofp 或
fptosi 转换。比较运算（> < >= <= == !=）对浮点走 fcmp，对整数走 icmp。
浮点不支持 % 取模与位运算符。

7. 异常处理 try / except
-------------------------------------------------------------------------------

    try{
        ...                      受保护语句
    }
    except <ErrorType>{          ErrorType 是编译期整数常量 / equ
        ...
    }
    except{                      不带 ErrorType = 通配，必须是最后一个分支
        ...
    }

规则：

  * 一条 try 至少有一个 except；可以有多个带不同 ErrorType 的分支，最后
    可选一个通配 except{}。没有 finally。
  * try / except 只能写在函数体内；支持嵌套；try} 与 except 之间可以夹
    普通语句（不能跨函数 / 跨段）。
  * except 的 ErrorType 必须是编译期常量表达式：数值、数值 equ、位运算。
    不能写字符串 / 函数调用 / addr / 结构体常量 / 比较逻辑表达式。
  * 保留标识符 fuck 是预定义的 4 字节全局变量；进入 except 分支时里面是
    本次异常的 ExceptionCode，可以直接读：int code=fuck。
  * 实现是 Windows x64 SEH：编译器为每个 try 生成 .pdata / .xdata unwind
    信息与 funclet，用 __C_specific_handler 作为 personality。首尾各有一个
    invoke 把 try 区域完整框住，因此整数除零、非法访问这类硬件异常也能被
    except 捕获，不只是函数调用抛出的异常。
  * try / except 体内的 return、break、continue 都走汇合点：先退出 funclet
    再返回 / 跳转，不会留下悬空的 SEH 帧。
  * except 处理器里的函数调用会自动带 funclet bundle。

示例：

    EXCEPTION_INT_DIVIDE_BY_ZERO equ 0C0000094h

    def guard(x:int) int{
        int r=0
        try{
            r=risky(x)
            try{
                r=r+1
            }
            except 0C0000005h{
                r=-4
            }
        }
        except EXCEPTION_INT_DIVIDE_BY_ZERO{
            r=-1
        }
        except{
            r=-3+fuck
        }
        return r
    }

8. 浮点（舍入 / 转换 / 混合运算规则）
-------------------------------------------------------------------------------

  * f32 -> float（4 字节 IEEE-754 binary32），f64 -> double（binary64）；
    LLVM 按类型自动使用 SSE / XMM 寄存器，形参走 XMM0~3，返回值走 XMM0。
  * 浮点字面量（3.14 / 1.25 / 2.0）一律按 double 生成；写入 f32 变量 /
    形参 / 结构体成员时再 fptrunc 到 float。float(...) 包裹非字面量
    表达式时先按原类型求值，再 sitofp 到 double（结果仍是 double，
    不会变成 float；要得到 float 请显式赋给 f32 变量或形参）。
  * 所有浮点运算按**默认 IEEE-754 语义**发射，编译器不加 fast-math：
    fadd / fsub / fmul / fdiv 的结果按 round-to-nearest-even（就近偶数）
    舍入；除零不抛异常，产生 ±inf / NaN；-O2 / -O3 只做常规优化，
    不改变舍入模式。
  * 浮点比较用有序谓词 fcmp oeq / one / olt / ole / ogt / oge：
    任一操作数为 NaN 时**全部返回 false**（包括「不等于」）。
    整数比较用无符号 icmp ult / ule / ugt / uge。

    混合运算与隐式转换（统一走 as_type）

      * 只要有一个操作数是浮点，就把两个操作数都提升到较宽的浮点类型：
          f64 + int  -> double（int 经 sitofp 转 double）
          f32 + f64  -> double（f32 经 fpext 转 double）
          f32 + int  -> float （int 经 sitofp 转 float）
        结果类型 = 提升后的类型；比较结果一律 i1（true/false）。
      * 两个都是整数 -> 统一到 i32 做整数运算（无符号 icmp / sdiv / srem）。
      * 浮点不支持 % 取模和位运算符（& | ^ << >> ~），编译器报错。
      * 赋值 / 实参 / return 都按「目标类型」转换：

          整数宽度变化    trunc（变窄，高位直接截断）/ sext（变宽，符号扩展）
          整数 -> 浮点    sitofp（按有符号整数转，round-to-nearest-even）
          浮点 -> 整数    fptosi **向零截断**（3.9 -> 3，-3.9 -> -3）；
                          超出目标整数范围或 NaN 时结果是 poison，
                          属于未定义行为，请先在源码里判断范围
          float <-> double  fpext（float->double，精确）
                            fptrunc（double->float，就近偶数舍入，
                                    可能溢出成 ±inf）

      * 例：`int ii=fv5`（fv5 是 f64）生成 fptosi double -> i32；
        `f32 s = fv1*2.0 + fv2`（右侧是 double）先按 double 算出结果，
        再 fptrunc 到 float 存入 s。
      * 结构体初值列表里的浮点成员按 IEEE 位模式写入，不经过运行期转换。

  * 用浮点时无需手动补 _fltused 或额外 CRT 库：编译器在 IR 里定义
    @_fltused（linkonce_odr，多文件联合链接不冲突）。

-------------------------------------------------------------------------------
9. 结构体传参与返回（Windows x64 ABI）
-------------------------------------------------------------------------------

  * 1 / 2 / 4 / 8 字节结构体：按值传，映射到 i8 / i16 / i32 / i64 寄存器。
  * 其它尺寸结构体：按指针传，调用方先拷一份临时副本再传地址。
  * 返回结构体：走隐藏 sret 指针（隐式首参），被调方把结果整块写回调用方
    提供的存储。接收端可以写赋值、局部初值或独立调用：

        struct big{ aa int  bb int  cc int }
        big gbig={1,2,3}
        def mkbig() big{
            return gbig
        }
        def start(){
            big a = mkbig()
            big b
            b = mkbig()
            mkbig()
            return 0
        }

  * 结构体成员读写、结构体形参与全局变量互传、嵌套 align 布局都按
    编译期 struct_offsets 的字节偏移生成。

10. 命令行附加参数 -addm / -addl
-------------------------------------------------------------------------------

    -addm[内容]     附加给 llc（编译命令）
    -addl[内容]     附加给 lld-link（链接命令）
    -addm "内容"    等价于把内容放在下一个 argv
    -addl "内容"

  * 方括号内的空格是普通字符，不做切分；也可以写成多个 argv，由编译器
    一直拼到遇见 ] 为止：

        cone -llvm:x64 -addl[ /libpath:Z:\masm64\lib64 user32.lib ] a.cone
        cone -llvm:x64 -addl[/libpath:Z:\masm64\lib64] -addl[user32.lib] a.cone

  * 内容原样拼接，不转义、不加引号、不展开 %1；多次给出按出现顺序累加。
  * -addm / -addl 为空内容会报「内容为空」并给出示例。
  * 源码里的 __compile__ "..." / __link__ "..." 等价于 -addm / -addl，
    命令行参数在前、源码指令在后，最后汇入同一条命令。
  * include 推导出的 .lib 也汇入链接命令，顺序在 -addl 之后。

11. 明确不支持的语法与替代做法
-------------------------------------------------------------------------------

    | 写法                    | 替代做法                                  |
    |-------------------------|-------------------------------------------|
    | win.* / win{}           | func 声明、import x64crt、include 对应库  |
    | asm{}（32 位内联汇编）  | 走默认 x86 后端（不带 -llvm）             |
    | asm64{}                 | 当前用纯 cone 语句                        |
    | seg 自定义段 / defined 宏 | 走默认 x86 后端                         |
    | 显式寄存器（eax 等）    | 走默认 x86 后端                           |
    | efunc                   | 改用 func 声明                            |
    | import 名字.dll         | include 名字.lib 或 func 声明             |
    | os.* 外部调用           | func 声明 CRT 函数或 import x64crt        |
    | 结构体常量 Type{...}    | 结构体变量初值列表 ={...}                 |
    | 32 位整数地址解引用     | 数组 / 结构体成员语法                     |
    | -llvm:x86               | 不带 -llvm 直接编译（默认 MASM32）        |

12. 诊断
-------------------------------------------------------------------------------

所有错误统一输出为：

    文件:行号: error: 具体问题 + 原因 + 建议做法

命令行参数错误输出：

    [cone] error: 具体问题 + 原因 + 建议做法

例如：

    a.cone:12: error: 外部函数 func foo 未写返回类型：请在声明行末补 int / long / f64 等
    a.cone:8:  error: x64 不支持显式寄存器 eax：32 位寄存器只在默认 x86 后端有效
    [cone] error: -addl[ 缺少右括号 ]；例：-addl[/libpath:Z:\masm64\lib64 user32.lib]

报错不带版本号、不带手册章节号、不带内部术语；链接失败时提示检查
.llvm.bat 的库路径 / -addl[...] / include xxx.lib。
